# Development Guide

**Project:** Nimbus

**Version:** 1.0.0

**Status:** Engineering Handbook

---

# 1. Purpose

This document defines the development workflow, coding standards, repository structure, testing strategy, and engineering conventions for Nimbus.

It ensures that every contributor follows the same practices, resulting in a consistent, maintainable, and production-ready codebase.

---

# 2. Project Overview

Nimbus is an AI-powered SaaS platform for retail businesses that helps optimize inventory and forecast product demand.

Core capabilities include:

* Demand forecasting
* Inventory optimization
* AI business assistant
* CSV imports
* Analytics dashboard
* Notifications
* Business management
* Voice assistant

# 7. Commit Convention

Format:

```text id="8hnw8x"
type(scope): description
```

Examples:

```text id="86ddtz"
feat(api): add inventory endpoint

fix(auth): refresh token validation

docs(database): update RBAC schema

refactor(ml): improve feature engineering
```

Types:

* feat
* fix
* docs
* refactor
* test
* chore
* perf
* ci

# 12. Database Workflow

Schema changes:

1. Update SQLAlchemy models.
2. Generate Alembic migration.
3. Review migration.
4. Apply locally.
5. Commit migration.

Never modify production tables manually.

---

# 13. API Development Workflow

When adding an endpoint:

1. Define schema.
2. Add route.
3. Add service.
4. Add tests.
5. Update `api.md`.
6. Update `api-schemas.md`.

---

# 14. Frontend Workflow

For every new feature:

* Create UI components.
* Add API service.
* Create React Query hooks.
* Add loading states.
* Handle errors.
* Ensure responsive layout.

---

# 15. Machine Learning Workflow

When improving forecasting:

1. Validate data.
2. Update preprocessing.
3. Train model.
4. Evaluate metrics.
5. Register model.
6. Update documentation.

Never replace production models without evaluation.

# 17. Documentation Rules

Every major change must update the relevant documentation.

Documents to maintain:

* architecture.md
* database.md
* api.md
* ml-pipeline.md
* authentication.md
* deployment.md
* security.md

Documentation is considered part of the codebase.

---

# 18. Pull Request Checklist

Before merging:

* Tests pass.
* Lint passes.
* Documentation updated.
* No secrets committed.
* Migrations reviewed.
* Feature verified.

---

# 19. Release Workflow

1. Merge into `development`.
2. Run CI.
3. Verify staging.
4. Merge into `main`.
5. Deploy.
6. Run health checks.
7. Tag release.

---

# 20. Error Handling

Backend:

* Return structured JSON errors.
* Avoid exposing stack traces.

Frontend:

* Display user-friendly messages.
* Log technical details separately.

---

# 21. Logging

Log:

* Requests
* Forecast generation
* Authentication events
* Background jobs
* Critical errors

Avoid logging sensitive data.

---

# 22. Performance Guidelines

* Prefer pagination for large datasets.
* Avoid N+1 database queries.
* Cache expensive operations where appropriate.
* Profile ML inference before optimization.

---

# 23. AI-Assisted Development

When using AI coding tools:

* Follow existing architecture.
* Respect documented APIs.
* Do not bypass RBAC.
* Keep generated code consistent with project conventions.
* Review all generated code before merging.

---

# 24. Code Review Standards

Reviewers should verify:

* Correctness
* Readability
* Security
* Performance
* Documentation
* Test coverage
* Consistency with architecture

---

# 25. Engineering Principles

Nimbus development follows:

* Simplicity first.
* Readability over cleverness.
* Documentation before implementation.
* Secure by default.
* Scalable architecture.
* Modular design.
* Automated testing.
* Continuous improvement.

---

# 26. Definition of Done

A feature is complete when:

* Implementation is finished.
* Tests pass.
* Documentation is updated.
* Code review is approved.
* CI succeeds.
* Feature is deployed successfully.
